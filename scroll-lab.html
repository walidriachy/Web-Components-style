01 — Page load

A timeline, not nine delays

The headline above splits into words, each rising from behind a clipping mask, then the supporting elements follow. One timeline sequences all of it — change the first duration and everything after it shifts automatically.

Why a timelineChaining with delay means recalculating every number by hand when one step changes.
Position parameter"-=0.4" overlaps the previous step. "<" starts alongside it.
The maskEach word sits in a wrapper with overflow:hidden, so it rises from nothing.
Reload to replayRefresh the page to watch the sequence again.
// split into masked words first
const words = splitWords(headline);

const tl = gsap.timeline({
  defaults: { ease: "power3.out" }
});

tl.from(words, {
    yPercent: 115,
    duration: 0.9,
    stagger: 0.045       // each word 45ms later
  })
  .to(".hero .fade", {
    autoAlpha: 1,
    y: 0,
    duration: 0.7,
    stagger: 0.09
  }, "-=0.55");      // overlap the words
02 — Scroll reveals

The workhorse: enter the viewport, animate once

Ninety percent of "nice scroll animation" is this one pattern. ScrollTrigger.batch groups whatever is on screen together so they stagger as a set rather than firing one at a time.

BatchedItems visible together animate together.
once: trueFires on first entry, then stops listening.
start: "top 85%"Trigger top hits 85% down the viewport.
Small distances16–24px. Large travel reads as cheap.
power2.outFast start, soft landing. Never linear.
Short0.5–0.7s. Anything slower feels broken.
ScrollTrigger.batch(".reveal", {
  start: "top 85%",
  once: true,
  onEnter: (batch) => gsap.to(batch, {
    autoAlpha: 1,
    y: 0,
    duration: 0.6,
    stagger: 0.08,
    ease: "power2.out"
  })
});

// set the start state in JS, not CSS, so the
// page is readable if the script never runs
gsap.set(".reveal", { y: 22, autoAlpha: 0 });
03 — Scrub

Tie progress directly to scroll position

With scrub, the animation has no duration of its own — the scrollbar becomes the playhead. Scroll back up and it runs backwards. A number rather than true adds catch-up smoothing.

0%
Scroll position drives this 
gsap.to(target, {
  value: 100,
  ease: "none",          // always none when scrubbing
  scrollTrigger: {
    trigger: "#scrubStage",
    start: "top 80%",
    end: "bottom 40%",
    scrub: 0.6          // 0.6s of catch-up smoothing
  },
  onUpdate: () => paint(target.value)
});

// scrub: true  → locked 1:1 to the scrollbar
// scrub: 0.6   → eases toward the scroll position
04 — Pin

Hold an element still and let scroll drive the content

The section below sticks to the viewport for three screen-heights while the scroll swaps what is inside it. This is the effect behind almost every product-tour page on the web.

const tl = gsap.timeline({
  scrollTrigger: {
    trigger: ".pinouter",
    start: "top top",
    end: "bottom bottom",
    pin: ".pinner",      // what stays fixed
    scrub: 0.5
  }
});

// ScrollTrigger goes on the TIMELINE,
// never on the tweens inside it
panels.forEach((p, i) => {
  if (i) tl.fromTo(p,
    { autoAlpha: 0, y: 40 },
    { autoAlpha: 1, y: 0 }, "+=0.4");
  if (i < panels.length - 1)
    tl.to(p, { autoAlpha: 0, y: -40 }, "+=0.6");
});
pin creates spacingScrollTrigger inserts padding equal to the pinned distance so the page below does not jump.
Give it roomThe outer element needs real height — here 280vh — or there is nothing to scroll through.
One trigger per timelineNesting ScrollTriggers inside a timeline is the most common way people break this.

05 — Horizontal scroll

Vertical input, horizontal movement

Pin the section, then translate a wide track sideways by exactly its overflow width. Keep these short — three or four panels. Long horizontal sections annoy people.

End the pin

Set end to the same distance.

const track = document.querySelector("#htrack");
const distance = track.scrollWidth - innerWidth;

gsap.to(track, {
  x: -distance,
  ease: "none",
  scrollTrigger: {
    trigger: "#hsec",
    start: "center center",
    end: () => "+=" + distance,  // function = re-read on resize
    pin: true,
    scrub: 0.6,
    invalidateOnRefresh: true
  }
});
Functions for endPassing a function means the value is recalculated on resize instead of freezing at load width.
invalidateOnRefreshTells GSAP to re-read start and end values when the layout changes.
Distance = timeThe pin lasts exactly as long as the horizontal travel, so nothing overshoots.
06 — Parallax

Different speeds imply depth

Move each layer a different amount across the same scroll range. Keep it subtle — under about 15% of viewport height. Anything more and the page feels like it is sliding apart.

Three layers, three speeds
gsap.utils.toArray("[data-speed]").forEach(el => {
  gsap.to(el, {
    y: () => el.dataset.speed,   // px of drift
    ease: "none",
    scrollTrigger: {
      trigger: "#plx",
      start: "top bottom",   // enters from below
      end: "bottom top",     // until fully past
      scrub: true
    }
  });
});

// negative = moves up faster = reads as nearer
07 — Counters

Numbers that count when they arrive

GSAP animates any object property, not just DOM nodes. Tween a plain number and write it out on each frame. snap keeps it on whole integers instead of showing 47.3819.

gsap.utils.toArray("[data-count]").forEach(el => {
  const obj = { n: 0 };

  gsap.to(obj, {
    n: +el.dataset.count,
    duration: 1.6,
    ease: "power2.out",
    snap: { n: 1 },        // whole numbers only
    scrollTrigger: { trigger: el, start: "top 88%", once: true },
    onUpdate: () => {
      el.textContent = obj.n.toLocaleString();
    }
  });
});
08 — Smooth scroll

The single most-copied detail on the web

That weighted, slightly-delayed scroll feel on award-winning sites is almost always Lenis. It is about twenty lines to wire up, and it is running on this page right now — compare it to the atlas page.

const lenis = new Lenis({
  lerp: 0.1,          // 0.05 heavy · 0.2 light
  wheelMultiplier: 1
});

// 1 · tell ScrollTrigger when Lenis scrolls
lenis.on("scroll", ScrollTrigger.update);

// 2 · drive Lenis from GSAP's ticker so both
//     run on one requestAnimationFrame loop
gsap.ticker.add((time) => lenis.raf(time * 1000));
gsap.ticker.lagSmoothing(0);
One loop, not twoRunning Lenis on its own rAF alongside GSAP causes visible jitter. The ticker fixes it.
lagSmoothing(0)Stops GSAP compensating for frame drops, which fights Lenis.
Use it sparinglyIt overrides native scrolling. On content-heavy sites plenty of people find it irritating.
09 — Micro-interaction

The magnetic button

Hover the button in the hero, or this one. It leans toward the cursor and springs back on exit. quickTo creates a reusable setter — far cheaper than a new tween on every mousemove.

const xTo = gsap.quickTo(btn, "x", { duration:0.4, ease:"power3" });
const yTo = gsap.quickTo(btn, "y", { duration:0.4, ease:"power3" });

btn.addEventListener("mousemove", e => {
  const r = btn.getBoundingClientRect();
  xTo((e.clientX - r.left - r.width  / 2) * 0.4);
  yTo((e.clientY - r.top  - r.height / 2) * 0.4);
});

btn.addEventListener("mouseleave", () => {
  xTo(0); yTo(0);
});
Putting it together

What is actually running on this page

Two libraries, about 60 KB gzipped between them. That is the whole trick.

gsap

The engine. Tweens, timelines, easing, the ticker.

ScrollTrigger

Ties any animation to scroll position. Pinning, scrubbing, batching, enter/leave callbacks.

lenis

Inertial smooth scroll. Roughly 3 KB.

gsap.matchMedia()

Reverts every animation automatically when a breakpoint stops matching — including prefers-reduced-motion.

Hand-rolled split

Splitting text into masked words is ten lines. GSAP's SplitText plugin does more, but is a paid Club feature.

Not used here

Three.js and WebGL. That is the next tier, and where the truly show-off sites go.
